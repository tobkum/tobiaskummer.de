The export archive

What “Export everything” in Ribband writes, for people and for other programs. One zip file:

library.json                     the whole library, lossless (Ribband imports it)
content/<id>-<hash>.html.gz      an article's text as Ribband stores it (gzip, UTF-8 HTML)
content/<id>/images.json         only with "Include pictures": picture address to file name
content/<id>/images/<file>       only with "Include pictures": the stored pictures
html/<title>.html                one page per article or bookmark
markdown/<title>.md              one Markdown file per article or bookmark
index.html                       everything, by list (Inbox, Archive) and by shelf (each in the shelf's own order)
README.txt                       for a person without the app: what is in the zip, how to open it, how to import it
manifest.json                    what the archive holds (the last entry)

library.json is always the first entry; the zip is read front to back. Items in Recently deleted are only in library.json (with "state":"trashed"), not in html/, markdown/ or the index.

library.json

One JSON document in the format Ribband’s sync also uses. It is written so that it can also be read line by line: the head on the first line, then each entity type as "<type>":[ with one record per line, then the counts on the last line.

An entity type without records is left out, in the records and in the counts.

  • Head: format is reader-export. schemaVersion is the major version: a reader that meets a higher one refuses the file and changes nothing. minorVersion only adds fields; a reader keeps fields it does not know and writes them back. exportedAt is milliseconds since 1970 in UTC, exportedAtUtc the same instant in ISO 8601. app names the app and its version.
  • Records: each is one entity, id plus its fields. Every time is milliseconds since 1970, UTC. Fields from newer versions keep their own names; unknown entity types are kept as they came.
    • tag: name, colour, mergedInto, purgedAt, and the tag’s extras (fields of newer versions) under their own names. A tag is never a shelf (format 1.4).
    • item: url, canonicalUrl, title (the page’s), userTitle (the user’s own, when renamed), siteName, author, excerpt, leadImage (address), wordCount, readingMinutes, language, state (inbox, archived, trashed; any other value, such as a newer version’s place, is shown in the Inbox and kept in the item’s extras), favourite, savedAt, archivedAt, trashedAt, purgedAt, extractionStatus, extractorVersion, contentRef (the hash of the stored text: the <hash> in content/), kind (article, or video, post and so on for bookmarks), the bookmark card’s previewTitleRaw, previewDescription, previewImageUrl, durationSeconds, pageCount, handle, titleSource, imageSource, goneSeenAt, goneAt, lastOpenedAt, textFailedAt, textRetriedAt, archiveCopy (format 1.6: the text is the Internet Archive’s copy of the page; the snapshot’s timestamp, yyyyMMddHHmmss).
    • itemTag: id <itemId>/<tagId>, added (true: the tag is on the item).
    • progress: id is the item’s; readPosition (0 to 1), readAnchor, listenPosition, finishedAt.
    • highlight: itemId, exact (the quote), prefix and suffix (a few characters around it in the article’s normalised text; empty when it has no anchor, as a highlight imported before its text), start (format 1.3: its offset there, a hint; null without an anchor), note, colour, createdAt, updatedAt (format 1.3: the last change of range or note), purgedAt (removed: the quote and note are cleared).
    • savedFilter (a saved search): name, query (the words), tagIds, shelfId, matchAll, place (inbox, archive or null; format 1.5), textState (format 1.6: Search’s “Links without text” filter, failed, gone or waiting, or null), createdAt, purgedAt.
    • shelf (format 1.4): name, createdAt, order (its place among the shelves, a fractional index key: base 62 digits compared as text), sort (the view its page shows; null for the default), mergedInto (joined into that shelf), purgedAt (removed or joined), and its extras.
    • shelfItem (format 1.4): id <shelfId>/<itemId>, added (true: the article is on the shelf), position (its place in the shelf’s own order, a fractional index key; ties by item id), addedAt (when it was put there). A shelf’s articles are its shelfItem records with added true, ordered by position; the records of a shelf joined into another count for that one (with the survivor’s own position first).
    • Before format 1.4 a shelf was a tag with shelvedAt (and shelfOrder, shelfSort), its articles links to it. Ribband reads such an export with those tags turned into shelves of the same id and their present links into the shelf’s articles in the order they were put on it (oldest at the top); the other tags lose the shelf fields.
  • Clocks (_hlc): per field, the hybrid logical clock of its last change, a string that sorts in time order (wall-clock milliseconds, a counter, the device id). An import merges exactly as sync merges another device: per field the newer clock wins, removals for good and “finished” stay, the same page saved twice becomes one item, same-named tags become one tag, same-named shelves are joined (the older shelf keeps its order, the other’s articles follow at its bottom). A record without _hlc (written by hand) fills empty fields and never overwrites anything.
  • Identity: items and tags are matched by id (a UUIDv7). An item saved separately under the same address (another id) is merged with the one there (the older id stays). A tag is matched by id, then by name (ignoring case and spacing). Items removed for good stay as tombstones (purgedAt set, content cleared) so an old export never brings them back.

content/

<itemId>-<hash>.html.gz is the article’s clean HTML exactly as Ribband stores and syncs it (<hash>: the first 32 hex digits of the SHA-256 of the HTML’s UTF-8 bytes; contentRef in the item). Pictures keep their original addresses in the HTML; with “Include pictures”, images.json maps each address to its file under images/. Without pictures an import fetches them again from their addresses.

html/, markdown/, index.html

For people. File names come from the shown title with \ / : * ? " < > | and control characters replaced, at most 80 characters, made unique with “ (2)”, “ (3)”. The Markdown files start with YAML front matter:

---
title: "My own title"
original_title: "The page's title"   # only when renamed
url: "https://example.com/a"
site: "Example"
author: "Ann Author"
saved: 2026-11-14T08:00:00Z           # ISO 8601, UTC
archived: 2026-11-15T09:00:00Z        # when archived
tags:
  - "tech"
shelves:
  - "Cooking"
state: archived
kind: video                           # bookmarks only
favourite: true                       # when true
progress: 0.42                        # when started
finished: 2026-11-15T10:00:00Z        # when finished
---

The body is CommonMark with GitHub’s tables and footnotes. Pages have no scripts.

Highlights in the pages, and “Export highlights”

Each article’s Markdown file and HTML page end with a section of its highlights, headed in the app’s language: per highlight its quote as a block quote, the day it was made in italics, its note as plain paragraphs. “Export highlights” (Pro) writes the same body: one .md file per article (a zip for several), plain Markdown or “For Obsidian” (YAML properties, and a ^hl-… block id after each quote).

Not in the archive

Reader settings (they belong to each device), the sync account and its state, what Ribband has learned about the layout of each site’s pages (each device learns it again), search indexes and device-local copies (preview images).
